# LibraDesk v0.2.0 — PDF metadata write-back and custom thumbnails

**Behavior change: manual book metadata and organization edits now update original PDF files. Atomic save is used without a persistent original-PDF backup.** Importing, reading and library record removal still do not rename, move or delete originals. Keep independent document backups if you need prior versions.

## What changed

- Edit title, authors, subject, genre, publisher, ISBN, year and language, with Info/XMP write-back to every attached PDF.
- Categories, tags, collections, favorite and reading status are embedded too, including updates after group renames/reparenting.
- Per-file queued/writing/saved/failed states, Retry/Stop, and failure notifications with View book.
- Durable replacement recovery, source-change guards and reader deferral. Filenames and page content stay unchanged.
- Choose PNG/JPEG/WebP thumbnails with preview, cancel, save and automatic-cover reset. Manual covers survive generated-cache cleanup and all database backups; they do not modify PDF pages.
- Migration 0010 preserves existing library data. Merely upgrading/importing does not queue source writes.

## Download and install

Download **LibraDesk_0.2.0_x64-setup.exe** below. Windows 11 x64 (Intel/AMD), current-user installation, bundled Microsoft WebView2 standalone prerequisite. No developer tools are needed. Close LibraDesk before upgrading; back up the library and source documents separately.

Suggested planning minimum: Windows 11-compatible dual-core x64 CPU, 8 GB RAM, 2 GB free working space plus source/index/backup storage, 1280 × 720 display. Metadata saves additionally need write access and room for a complete staged file in the source folder. Hardware recommendations are not a measured minimum. The app/installer are unsigned.

## Source-write limits

Writable, unsigned, unencrypted PDFs up to 256 MiB are supported. EFS-encrypted, locked, read-only, changed or unsupported files fail visibly; the catalog edit remains saved. Close other editors before retrying. Only Saved to PDF confirms completion.

No persistent PDF backup or metadata undo history is created. Stop prevents pending work and does not undo completed writes. Incremental revisions may retain old metadata bytes; secure erasure and PDF/A conformity are not promised. Other viewers may not display custom taxonomy properties, and a fresh import does not reconstruct all custom organization.

Notes/bookmarks/progress/custom thumbnails remain library data. Database restore cannot undo source metadata and does not replay restored write jobs. Finish/stop prepared saves before library restore or removing their file records.
